## 📁 **Dossier mémoire** : [./memory/](./memory/) / [~/.config/opencode/memory/](~/.config/opencode/memory/)

### ✅ **Règles de base**
1. **CRITIQUE - TOUT doit être noté** : Pas seulement le critique, enregistrez **TOUTE l'activité**
2. **Chronologie stricte** : Ordre temporel respecté
3. **Titres courts** : Max 5 mots maximum
4. **Pas de doublons** : Ne réécrivez jamais la même information multiple fois dans une session

### 🔍 **PROCÉDURE OBLIGATOIRE - D'abord vérifier la mémoire du jour !**
- **À chaque début de session, consultez systématiquement le dossier mémoire actuel**
  - Format : `/2026/10/30/` (année/mois/jour)
- **Pourquoi ?** Si vous commencez une tâche aujourd'hui, quelque chose pourrait être arrivé ce jour-là sur ce sujet
  - Exemple : "Tu note pas assez ta mémoire" → Vous avez déjà créé `memory-comprehensive.md` avec cette note
  - Conséquence : Ne réécrire pas le même problème, mais **continuer de suivre les bonnes pratiques**, et à la place modifier le fichier actuel `memory.md` pour renforcer le comportement

### 📅 **Structure du dossier**
- Format : `<année>/<mois>/<jours>/` (ex: `/2026/10/30`)
- Création automatique si le dossier n'existe pas

### 📝 **Types de documents à créer**

| Document | Contenu | Quand créer |
|----------|---------|-------------|
| `memory-comprehensive.md` | **TOUTE l'activité en détail** | À chaque session importante |
| `memory-note.md` | Notes clés et progressions | Quand on gagne une connaissance clé |
| `test-task.md` | Tests et tâches techniques | Pour documents tests et vérifications |
| `memory-interactions.md` | Interactions utilisateur-agent | Pour documenter les échanges |

### 🔄 **Processus d'archivage**
1. Vérifier le dossier `/2026/10/30/` à chaque début de session ⭐⚠️
2. Si un nouveau fichier doit être créé, nommer-le selon le contexte
3. Documenter les tâches, problèmes, progrès ET petites interactions
4. Utiliser tableaux et checklists pour vue d'ensemble

| Type | Priorité | Détails requis |
